# 广告替换与信号失效检测：资料与边界

本笔记区分文档事实和项目设计推论。具体样本统计及落地顺序见 [检测方案](content-detection-plan.md)。

## 可以直接采用的基础能力

- FFmpeg `freezedetect` 检测指定时长内画面是否缺少显著变化，产生冻结起止信息。它检测的是变化量，并不判断节目内容是否正确。因此凤凰香港失效页与 CCTV10 正常停播卡都可能命中，必须在上层解释。[FFmpeg 官方实现](https://ffmpeg.org/doxygen/trunk/vf__freezedetect_8c.html)
- OCR 前处理需要考虑缩放、二值化、噪声、边缘与页面分割方式；Tesseract 默认针对文字页面，小区域应选适当分割模式。因此建议将台标角落、中央提示文字、底部广告字幕分别裁切后识别，保存原图和置信度，不能将 OCR 未识别出文字等同于没有台标。[Tesseract 图像质量与分割说明](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)
- Tesseract 支持指定识别语言及多语言组合。中文提示和英文 `NO SIGNAL` 可使用对应语言数据；使用前检查本机可用语言，OCR 不可用时应记录“未检测”。[Tesseract 命令行说明](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html)

## 设计推论：失效检测先做，广告替换采用组合证据

“信号暂时失效 / 信号中断 / NO SIGNAL”等文字在多个采样时点持续出现，且主体画面保持静态，可构成信号失效候选；单帧出现这些词可能是新闻字幕。正确台标并不能抵消明确的失效提示，凤凰香港就是反例。CCTV10 已人工确认的停播卡应保留，不能因为静态或彩条直接判失效。正常源、停播卡、失效页需要共同进入验证集。

广告相关文字如订购热线、疗效宣传和二维码只能说明内容可能是广告。自动判断“冒充目标频道”还需要其他证据：反复识别到另一个台标；不同频道持续出现同一路推销内容；与经过确认的同频道参考源在多个窗口始终不一致。正确台标是支持证据，也可能被叠加或伪造，不宜设置为无条件通过。

画面感知指纹用于相似候选检索，不能赋予语义。同一广告经过编码、缩放仍可能相似，但新广告可能完全不匹配；纯色、测试卡、公共片头也可能误碰。已知广告匹配只能补充证据。若做阈值，必须在本项目不同分辨率和画面类型上校准，不能声称某个固定距离天然可靠。

跨源对照需记录真实采样时间并允许直播延迟。比较短序列并搜索时间偏移，比比较同一秒单帧更合理。未在采样窗口找到相同内容只能标注“没有匹配证据”；参考源可能自身错误，多个主机也可能转发同一上游。正常新闻联播、同步广告是必须加入的负例。

## 如何证明能发现新广告

1. 先按 URL、主机和画面内容整理标注，人工合并属于同一广告或相同失效模板的样本。
2. 按广告内容组留出完整未知广告，并尽可能按主机留出；同一广告的三个时点截图不能拆到训练和测试两侧，否则只证明记住画面。
3. 分别报告已知画面检索、新广告待审召回、失效检出和正常源误报；同时报告进入人工队列的数量。小样本不应给出过度精确的泛化承诺。
4. 必测反例：正确台标的正常广告、正确停播测试卡、新闻中出现失效文字、跨频道正常联播、不同延迟与短暂丢帧。
5. 第一版仅输出原因、证据截图、相似源及候选状态至 HTML 审核；保留人工裁定优先级，验证后再逐项开放自动隔离。

以上组合判据和验证方法是针对本项目的工程建议，并非 FFmpeg 或 Tesseract 提供的成品广告分类器。

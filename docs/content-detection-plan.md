# 广告替换与失效源检测实施方案

## 目标与已有证据

目标是识别源是否输出目标频道，而不是过滤电视节目中的广告。
暂时停播但频道正确的测试卡允许发布；未知情况交由用户在 HTML 中审核。

本地证据：`audits/2026-09-07-multiframe/stream-review.json` 有 23 条
wrong_channel、2 条 signal_lost；338 张截图位于相邻 frames 目录。
23 条错台分布于 4 个服务器地址，其中 19 条集中在两个地址。
因此这批记录不是 23 个独立广告活动；不能随机拆分同广告的截图后宣称能识别新广告。
未经审核的其他图片也不能默认当作正常样本。

## 第一阶段：补足证据采集（只生成审核建议）

1. 每次审计创建唯一目录并保存 manifest.json，含源标识、标准频道、原始名称、
   UTC 请求/截图时间、媒体时间（若可取得）、图片路径、错误、规则版本。
   旧文件不得混入本次结果，成功必须验证输出图像存在且可读取。
2. 首轮取得短片内多帧；仅对可疑源在真实时间约 60 秒、180 秒后重新连接取样。
   这些是初始试验参数，不是已验证的分类阈值。
   同频道对照源应在同一轮采集，允许节目延迟；无法对齐时返回未知。
3. 对保存的图片离线提取：全图与角落区域感知哈希、OCR 文本及位置/置信度、
   台标候选、帧间变化。中文 OCR 可先试 PaddleOCR；图形台标需另行模板匹配，
   OCR 没读到台标不能解释为台标不存在。
4. 感知哈希寻找已知画面近似匹配和跨频道候选组；用多个时间点验证候选，
   保留参考图片和距离。它不能单独识别新广告，也不能据此认定来自独立上游。

建议模块：`scripts/review_stream_content.py` 负责取证，新增
`my_tv_collect/content_evidence.py` 负责离线特征，
`my_tv_collect/content_decision.py` 根据证据生成状态，HTML 展示证据和接收人工反馈。
OCR 和阈值均可替换，不与采集、发布耦合。

## 第二阶段：组合判断

| 证据组合 | 建议状态 | 动作 |
|---|---|---|
| 本频道台标 + 测试卡且无失效提示 | OFF_AIR / 待确认 | 已人工确认则继续发布；新样式待审 |
| 多帧失效提示文字 + 提示页布局/长期固定画面 | SIGNAL_LOST_CANDIDATE | 复检并交人工；新闻里出现相关文字不能据此隔离 |
| 多次检测到明确的其他频道台标 | WRONG_CHANNEL_CANDIDATE | 展示角落证据，交人工确认 |
| 推销文字 + 目标身份未确认 + 跨不同频道持续重复内容 | AD_REPLACEMENT_CANDIDATE | 即使从未见过该广告，也进入审核 |
| 同频道已核验对照源一致、候选长期不同 | CONTENT_MISMATCH_CANDIDATE | 排除延迟和地区版本后人工确认 |
| 仅电话号码、二维码、正常广告或台标缺失 | UNKNOWN | 不据此永久拒绝 |

不同域名/IP不等于独立来源，多数源也可能同时被污染。跨频道正常联播也可能
高度相似，必须保留频道身份信息。正确台标同样不是绝对保证：可以被伪造或覆盖。

初期所有新内容规则只出审核建议，不自动扩展永久拒绝名单。
已有人工拒绝/隔离继续执行；技术层的无视频轨、连接失败另行展示。
规则经过留出样本验证后，才评估是否将高可靠的失效页面检测自动用于暂时隔离。

## HTML 审核改进

每项展示：具体触发原因、原图、角落裁剪、OCR 命中文字、匹配到的其他源、
真实采样时间、历史人工结论。例如“3 次复检中有 2 次与另外 4 个频道的图片相似”，
不能只显示“疑似广告”。

已有人工结论也必须能被新证据重新触发审核：URL 可以换内容。
不要让一个 decision 字段永久阻止后续审核。正常确认保留为历史标签，
不等于以后任意画面均放行。`uncertain` 不映射为拒绝。
隔离记录要有下一次复检时间；目前 quarantine 直接跳过检测，尚未实现自动恢复。

## 验证与交付次序

1. 保存现有样本及人工标签，建立可重复运行的离线评估。
2. 加真实时间复检与 manifest，再接 OCR、哈希和可解释候选规则。
3. 用广告内容簇/活动分组留出，并做留一服务器评估；同一广告的不同分辨率、
   不同 URL 和多张截图不得分别进入开发与测试。另收集未来日期的新广告测试泛化。
4. 增补人工确认正常样本：正常商业广告、夜间测试卡、联播、无台标过渡镜头。
   特别检查 CCTV10 不被当失效源，以及凤凰香港提示页能进入审核。
5. 分开报告候选查准率、已标注异常召回率、正确源误报数量、未知数量和审核工作量。
   原先只挑了重复画面供审核，样本有选择偏差；对未入选源随机抽检才能估计漏检。
6. 第一版交付为新的 HTML 候选报告和评估结果；不承诺尚未测得的准确率。

## 现有实现需一并纠正的边界

- JPEG SHA256 仅证明文件相同，不是语义识别。
- fps 滤镜的媒体时间采样不等于真实时间延迟复检。
- FFmpeg 返回成功不能单独证明已输出视频帧，需强制选择视频轨并验证输出。
- 不应把仅凭正常化后名称不同的共享 URL 直接视为已证实错台，未确认别名需待审。
- 样本匹配分数、OCR 置信度不等于“这是广告替换”的概率。
